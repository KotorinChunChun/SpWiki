# テナント管理者向け

SpWiki 1.0 の導入・設定・運用の手順です。
概要は [README.md](../README.md)、構成・運用上の注意事項は [TECHNICAL_REFERENCE.md](TECHNICAL_REFERENCE.md) にあります。

やることは 3 つで、**必須は 1 だけ**です。

| # | 作業 | 必須 | 所要 |
| --- | --- | --- | --- |
| 1 | `.sppkg` をアプリ カタログに配置 | 必須 | 5 分 |
| 2 | ライブラリのコマンドを登録 | 任意 | 5 分 ＋ 反映待ち数分 |
| 3 | `spmd:` に対応したアプリを用意 | 任意 | 環境による |

---

## 1. アプリ カタログに配置する

### 1.1 アップロード

1. `https://<テナント>.sharepoint.com/sites/appcatalog` を開く
   （無い場合は SharePoint 管理センター →「その他の機能」→「アプリ」→「アプリ カタログ」で作成）
2. **「SharePoint のアプリ」(Apps for SharePoint)** ライブラリを開く
3. `packages/<バージョン>/SpWiki.sppkg` をドラッグ＆ドロップ
4. 信頼を確認するダイアログで **「展開」(Deploy)** を押す

> ### ファイル名を変えないでください
>
> アプリ カタログは**ファイル名**でパッケージを同定します。
> `SpWiki-1.0.0.0.sppkg` のようにバージョンを付けると置き換えにならず、
> 「同じ製品 ID を持つソリューションが既に存在します」で `Disabled` になります。
> バージョンはフォルダー名で管理しているので、**ファイル名は常に `SpWiki.sppkg`** です。

### 1.2 テナント全体に展開する

「**このソリューションをすべてのサイトで利用できるようにする**」に**チェックを入れてください**。

- サイトごとのアプリ追加が不要になります
- **ライブラリのコマンド（手順 2）を使うには、この展開が前提です**

このソリューションは `skipFeatureDeployment: true` なので、このチェックが選べます。

テナント全体展開をしない場合は、対象サイトごとに
歯車 →「アプリの追加」→「SpWiki」で追加します。

### 1.3 確認

対象サイトでページを編集し、セクションの **＋** →「詳細設定」(Advanced) カテゴリに
**「SpWiki」** が出れば配置完了です。

ページの作り方は [WRITERS_GUIDE.md](WRITERS_GUIDE.md) を参照してください。

## 2. ライブラリのコマンドを登録する（任意）

ライブラリで `.md` を選んだときに、ツールバーと右クリック メニューへ 3 つのコマンドを出します。

| コマンド | 動作 |
| --- | --- |
| SpWiki で開く | ビューアー ページへ遷移 |
| Markdown プレビュー | ライブラリ上にモーダルを開いて描画 |
| デスクトップ アプリで編集 | `spmd://` でローカルのエディターに渡す |

### 2.1 テナント全体の拡張機能リストに 1 行足す

`elements.xml` もフィーチャー定義も不要です。

`https://<テナント>.sharepoint.com/sites/appcatalog/Lists/TenantWideExtensions` を開いて新規作成します。

| 列 | 値 |
| --- | --- |
| タイトル | `SpWiki Command Set` |
| コンポーネント ID | `7bf4c5c5-631b-48cf-b066-e92bfb4c91dc` |
| コンポーネント プロパティ | 下記 JSON |
| 場所 | `ClientSideExtension.ListViewCommandSet` |
| リスト テンプレート ID | `101`（ドキュメント ライブラリ） |
| シーケンス | `1000` |
| ホストのプロパティ | (空欄) |
| 無効 | いいえ |

```json
{
  "viewerPageUrl": "/sites/<サイト>/SitePages/<ビューアー ページ>.aspx",
  "chromeMode": "WebView"
}
```

> `viewerPageUrl` は**ビューアー ページを置いたサイトのパス**です。ここを別サイトのまま
> にすると「SpWiki で開く」が存在しないページへ飛びます。ページの URL から
> `?file=...` を取り除いたものをそのまま貼ってください。

**反映まで数分かかります。** すぐ出なくても少し待ってください。

### 2.1.1 `viewerPageUrl` の設定と反映

登録内容の反映には時間がかかる場合があります。設定後はページを再読み込みし、
「SpWiki で開く」の遷移先を確認してください。
`viewerPageUrl` が未設定の場合は、設定を案内するダイアログが表示されます。

### 2.1.2 コマンドが 1 つも出ないとき

こちらは**表示そのものが無い**場合です（上の「押しても無反応」とは別物）。

1. **ファイルを 1 つだけ選択しているか。** コマンドは `.md` / `.markdown` / `.html` /
   `.htm` が**ちょうど 1 つ**選ばれているときだけ出ます。フォルダーや対象外の拡張子、
   複数選択、未選択ではすべて隠れます。
2. **ソリューションがテナント全体に展開されているか。** アプリ カタログの「アプリの管理」
   で「すべてのサイトで利用可能」が**はい**になっているか。
3. **同じ製品 ID の古いパッケージが残っていないか。** 残っていると新しい方が
   `Disabled` で取り込まれます。
4. **拡張機能の JS が読み込まれているか。** ライブラリのページで F12 →ネットワークを開き
   `sp-wiki-command-set` で絞り込みます。読み込まれていなければ 2 か 3、
   読み込まれているなら 1 が原因です。

### 2.2 「場所」の値でコマンドの出る先が変わる

| 値 | ツールバー | 右クリック メニュー |
| --- | --- | --- |
| `ClientSideExtension.ListViewCommandSet.CommandBar` | 出る | 出ない |
| `ClientSideExtension.ListViewCommandSet.ContextMenu` | 出ない | 出る |
| `ClientSideExtension.ListViewCommandSet` | **出る** | **出る** |

両方に出すために行を 2 つ作る必要はありません。

### 2.3 コンポーネント プロパティ

| キー | 既定 | 説明 |
| --- | --- | --- |
| `viewerPageUrl` | (なし) | ビューアー ページ。絶対 URL / サーバー相対 / ファイル名のみ（サイトの `SitePages/` 基準）。**未設定だと「フルページで開く」がその旨のダイアログを出します**。書き換えの反映には時間差があります（2.1.1） |
| `libraryRootUrl` | (空) | `?file=` の基準にするフォルダーのサーバー相対 URL。空欄ならコマンドを実行したライブラリのルート |
| `chromeMode` | (空) | `Embedded` / `WebView`。ビューアー URL に `env=` を付けます。最小クロームは `WebView` |
| `openInNewTab` | `false` | フルページを新しいタブで開く |
| `appProtocol` | `spmd` | 「デスクトップ アプリで編集」が使う URL スキーム |
| `showFullPageCommand` | `true` | コマンドの表示切替 |
| `showPreviewCommand` | `true` | コマンドの表示切替 |
| `showOpenInAppCommand` | `true` | コマンドの表示切替 |

> ### `libraryRootUrl` の合わせ方
>
> Web パーツの「ライブラリ名」が `Shared Documents` なら空欄のままで合います。
> `Shared Documents/md` のようにサブフォルダーを指しているときは
> `"libraryRootUrl": "/sites/<サイト>/Shared Documents/md"` を指定してください。
> ずれていると「フルページで開く」の `?file=` が実ファイルと一致しません。

### 2.4 特定のライブラリだけに入れる場合

PnP PowerShell を使います。

```bash
Connect-PnPOnline -Url https://<テナント>.sharepoint.com/sites/docs -Interactive
```

```bash
Add-PnPCustomAction -Title "SpWiki" -Name "SpWiki" -Location "ClientSideExtension.ListViewCommandSet" -ClientSideComponentId 7bf4c5c5-631b-48cf-b066-e92bfb4c91dc -ClientSideComponentProperties '{"viewerPageUrl":"/sites/<サイト>/SitePages/SpWiki.aspx","chromeMode":"WebView"}' -List "Shared Documents" -Scope Web
```

## 3. `spmd:` スキーム（任意）

ページ右上の「アプリで開く」は既定で非表示です。表示する場合はページを編集し、
Web パーツの設定の「ツールバー」で
**「右上に「アプリで開く」ボタンを表示する」**を ON にしてください。
OFF にするとボタンを非表示にできます。設定を保存してページを公開してください。
明示的に ON で保存してあるページは、その設定を維持します。

「デスクトップ アプリで編集」「アプリで開く」は、**カスタム URL スキームを開くだけ**です。
そのスキームに対応したアプリを、利用者の PC 側で用意してください。

SpWiki が投げるのは、**ファイルの SharePoint URL のスキームを差し替えたもの**だけです。

```
https://<テナント>.sharepoint.com/sites/docs/Shared%20Documents/md/README.md
spmd://<テナント>.sharepoint.com/sites/docs/Shared%20Documents/md/README.md
```

**それ以外は何も渡しません。** ファイルがローカルのどこにあるかは PC ごと・ユーザーごとに
違うので、受け取ったアプリ側で解決してください（OneDrive の同期先を見る、WebDAV の
UNC パスに変換する、など）。

### 3.1 スキーム名を変える

Web パーツのプロパティ「URL スキーム」で変更できます（既定は `spmd`）。
拡張機能を使う場合は、コンポーネント プロパティの `appProtocol` も同じ値にしてください。

### 3.2 未対応でも実用になります

対応アプリが登録されていないと、ブラウザーは**黙って何もしません**。
SpWiki はフォーカスが戻ってきたかどうかで判定し、

> アプリを起動できませんでした。spmd: に対応したアプリがこの PC に登録されているか確認してください。

と表示します。ページの閲覧そのものには影響しないので、
スキームを配布しない運用でも問題ありません。

## 4. 更新版を配る

```bash
pwsh -File dev/scripts/release.ps1 -Bump Build
```

1. 新しい `SpWiki.sppkg` を同じアプリ カタログにアップロードして上書き
2. 「展開」を押す
3. サイト側は「サイト コンテンツ」でアプリの更新が案内されたら適用

Web パーツの設定値はページ側に保存されているため、更新後も保持されます。

> ### バージョン番号を必ず上げてください
>
> アプリ カタログはバージョン番号で更新を判定します。番号を上げずに再アップロードすると、
> 旧バンドルが配信されたままになることがあります。

### 壊れた行が残った場合

`状態 = Disabled` / `有効なアプリ パッケージ = No` の行ができてしまったら、
その行を選んで **「削除」** してから、正しいファイル名で入れ直してください。

## 5. 権限

### 5.1 「アクセス」ボタンで限定公開にする

ファイル名の左にある**鍵アイコン**をクリックすると、**「アクセス許可」の画面**が開きます。
そこから、開いているフォルダーやファイルを限定公開にできます。
変更はドキュメント ライブラリにそのまま反映されます（SharePoint の権限そのものを操作します）。

**まず「引き継ぎ」の仕組みを押さえてください。**

SharePoint では、フォルダーやファイルは**上のフォルダーの設定をそのまま引き継ぎます**。
どこかで引き継ぎをやめると、そこから下は別の設定になります。

```
Shared Documents/          ← サイト全員が見られる
└─ 人事/                   ← ここで引き継ぎをやめて、人事部だけに限定した
   ├─ 評価.md              ← 人事部だけ（人事/ から引き継ぎ）
   ├─ 給与/                ← 人事部だけ（人事/ から引き継ぎ）
   │  └─ テーブル.md        ← 人事部だけ（給与/ 経由で引き継ぎ）
   └─ 公開資料/ 🔒          ← ★以前に別の設定をしていた場合、ここだけ変わらない
```

| 設定した対象 | どこまで効くか |
| --- | --- |
| **フォルダー** | その中のフォルダーとファイルすべて。ただし**すでに個別の設定を持っているものには効きません** |
| **ファイル** | そのファイルだけ |

### 5.1.1 「ここでの設定が反映されない項目」を必ず見てください

上の図の `公開資料/` のように、**すでに個別の設定を持っているものは、親を限定公開にしても
変わりません**。「人事フォルダーを閉じた」つもりでも、その中の 1 つだけ全員に見えたまま、
ということが起こります。

そのため、アクセス許可の画面には **「ここでの設定が反映されない項目」** という一覧が出ます。
ここに何か並んでいたら、**それは限定公開にならずに残る項目**です。
必要であれば、その項目を開いて 1 つずつ設定してください。

一覧に何も出なければ、そのフォルダーを限定公開にするだけで中身すべてに効きます。

### 5.1.2 鍵アイコンで状態が分かります

ファイル名の左の鍵が、そのページの状態を表します。

| アイコン | 意味 |
| --- | --- |
| 開いた鍵 | 上のフォルダーの設定を引き継いでいます |
| 閉じた鍵（オレンジ） | このページ専用の設定を持っています（限定公開） |

**一覧のツリー表示**（サブページ一覧・ページツリー・検索結果・フォルダーを開いたとき）でも、
限定公開の項目には名前の右に閉じた鍵が付きます。フォルダーにも付きます。

棚卸しをするときは、**検索ページの「限定公開のみ」**にチェックを入れてください。
検索文字列が空でも動くので、そのままライブラリ全体の一覧になります。
「検索するフォルダー」と組み合わせれば範囲を絞れます。

### 5.2 操作の安全策

- **引き継ぎをやめるとき、今の設定をそのままコピーします。** 実行した瞬間に誰かが締め出されることはありません。
  そこから不要な相手を外していく手順になります
- **「親の設定に戻す」を必ず併設しています。** やり直せない操作にはしていません
- **どちらも確認が必須です。** 対象のパスと、何が起きるかを文章で出したうえで確定します

> ### ファイル単位の設定は例外にしてください
>
> SharePoint は個別権限の数が増えるとライブラリ全体が重くなります
> （目安 5,000 件、上限 50,000 件）。**フォルダー単位を基本**にしてください。
> ファイルを対象にしたときは、確認の画面にも警告が出ます。

### 5.3 指定できる相手

SharePoint グループ・個人・**Entra ID のセキュリティ グループと Microsoft 365 グループ**を
指定できます。サイトで一度も使われていないディレクトリ上のグループは、付与するときに
自動でサイトに登録されます（`ensureuser`）。

権限レベルは「閲覧」「編集」などサイトに定義されているものから選びます。
**「フル コントロール」と「制限付きアクセス」は選択肢に出しません**
（前者はここで配るものではなく、後者は SharePoint が内部的に付けるものです）。

### 5.4 必要な権限

| 操作 | 必要な権限 |
| --- | --- |
| `.sppkg` のアップロードと展開 | アプリ カタログの管理者 |
| テナント全体の拡張機能リストへの登録 | アプリ カタログの管理者 |
| ページの作成・Web パーツの配置 | 対象サイトの編集権限 |
| Markdown の閲覧 | ライブラリの閲覧権限 |
| **タグの保存** | **ライブラリの編集権限** |

閲覧のみのユーザーにもタグの編集画面は開けますが、保存時にエラーになります。
編集画面を開かせない場合は、Web パーツの設定で
「列名をクリックしてタグを編集できるようにする」を OFF にしてください。
OFF にしてもタグの表示と、タグをクリックする検索機能は利用できます。

Markdown の取得はログインしているユーザーの権限で行われます。
**ビューアーが権限を迂回することはありません。**

## 6. トラブル対応

| 症状 | 確認すること |
| --- | --- |
| Web パーツ一覧に出てこない | アプリ カタログで「展開」を押したか。テナント全体展開をしていないならサイトへのアプリ追加が済んでいるか |
| `ドキュメントライブラリが見つかりません。` | ライブラリ名の設定。**日本語サイトの既定ライブラリはタイトル「ドキュメント」／フォルダー名 `Shared Documents`** で、`Documents` はどちらにも一致しません |
| ライブラリにコマンドが出ない | テナント全体展開をしたか。拡張機能リストの行（コンポーネント ID・場所・リスト テンプレート ID `101`）。反映に数分かかります |
| コマンド名が英語で出る | ブラウザーのキャッシュをクリア |
| コマンドは出るが押しても何も起きない | `viewerPageUrl` が拡張機能に届いていません。登録行を直しても反映に時間差があります（2.1.1）。未設定の場合は案内ダイアログが出ます |
| フルページで開くと 404 | `libraryRootUrl` と Web パーツの「ライブラリ名」がずれています（2.3 の注意） |
| `Markdownファイルが見つかりません。` | `?file=` のパスが実ファイルと一致しているか。パスはライブラリのルート基準 |
| タグの段が出ない | Web パーツのプロパティで「タグの列」を選んだか |
| タグを保存できない | ライブラリの編集権限。選択肢列の場合、値が列の選択肢に登録されているか |
| 画像が出ない | ライブラリ内の相対パスになっているか。外部 CDN と `data:` URI は既定でブロックされます |
| 更新したのに古い内容が出る | `.sppkg` のバージョンを上げたか。ブラウザーのキャッシュをクリア |
| ページを開くと空 | 開発者ツールでコンソールとネットワークを確認。REST が 403 ならライブラリへの閲覧権限 |

## 7. 画面の見せ方を変える

ページ URL にクエリを足すと、SharePoint のナビゲーション類を隠せます。

```
https://<テナント>.sharepoint.com/sites/docs/SitePages/SpWiki.aspx?file=README.md&env=WebView
```

| 要素 | 通常 | Single Part App Page | `env=Embedded` | `env=WebView` |
| --- | --- | --- | --- | --- |
| 左ナビ | 出る | 出る | 消える | 消える |
| サイト ヘッダー | 出る | 出る | 消える | 消える |
| コマンドバー（「編集」の帯） | 出る | 出る | 消える | 消える |
| アプリ バー | 出る | 出る | 消える | 消える |
| ハブ ナビ | 出る | 出る | 残る | 消える |
| スイートバー（最上部） | 出る | 出る | 残る | 消える |
| 幅 | セクション幅 | やや狭い | ほぼ全幅 | ほぼ全幅 |

**最小クロームは `?env=WebView`** です。

> `?env=` は SharePoint の JS に実装されていますが**ドキュメント化されておらず非サポート**です。
> 将来予告なく動かなくなる可能性があります。

### 利用者に編集させたくない場合

ページを Single Part App Page に変換します。**クロームは減りません**が、
レイアウトがロックされて利用者はページを編集できなくなります。

```bash
Set-PnPPage -Identity md1 -LayoutType SingleWebPartAppPage
```

**変換すると Web パーツの設定をブラウザーから変更できなくなります。**
設定を済ませてから変換してください。戻すには `-LayoutType Article` です。

PnP を入れられない環境向けに、ブラウザーの開発者ツールに貼るだけで同じことをする
[dev/scripts/set-page-layout.js](../dev/scripts/set-page-layout.js) を用意してあります。
