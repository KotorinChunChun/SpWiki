# 書く人（ライター）向け

Markdown（または HTML）を書いて公開するまでの手順です。
**特別なツールは不要です。** ライブラリに `.md` を置けば、そのまま読めるようになります。
`.html` も同じように置けます（→ [10. HTML ファイルを置く](#10-html-ファイルを置く)）。

読む側の操作は [USERS_GUIDE.md](USERS_GUIDE.md) にあります。

---

## 1. ファイルを置く

ドキュメント ライブラリに `.md` をアップロードするだけです。
ビューアーの **☰ メニュー →「新しいページを作成」** からその場で作ることもできます。
ファイル名・形式（`.md` / `.html`）・作成後の編集先（SharePoint / デスクトップ アプリ）を
指定すると、見出しと `## 目次` が入ったひな形ができ、そのまま編集画面に移ります。
ファイル名やフォルダーを後から変えたいときは、上に出ているファイル名をクリックしてください。
**フォルダー構成がそのままリンクの基準**になります。

```
ドキュメント
├─ README.md          ← 最初に表示されるファイル
├─ guide
│   ├─ index.md
│   ├─ install.md
│   ├─ update.md
│   └─ faq.md
└─ images
    ├─ logo.png
    └─ sample.png
```

- 文字コードは **UTF-8** にしてください
- 拡張子は `.md` `.markdown` `.html` `.htm`
- フォルダーは何階層でも構いません
- 日本語のファイル名・フォルダー名も使えます

---

## 2. リンクの書き方

ここがこのビューアーの中心です。**GitHub と同じ感覚で書けます。**

### 同じフォルダーのファイル

`guide/index.md` の中で:

```markdown
[インストール手順](install.md)
```

→ `guide/install.md` が開きます。

### 上のフォルダーのファイル

`guide/install.md` の中で:

```markdown
[トップに戻る](../README.md)
```

→ `README.md` が開きます。

### ライブラリのルートから指定する

先頭に `/` を付けます。どのファイルから書いても同じ場所を指します。

```markdown
[トップに戻る](/README.md)
```

### 目次を自動生成する

**`## 目次` という見出しを置くだけ**で、その下にページ内の見出しツリーが自動で作られます。
見出しを増やしても目次は自動で追いつくので、手で書く必要はありません。

```markdown
# インストール手順

## 目次

## 前提条件

## 手順

### 1. ビルド
```

- 見出しのテキストが**ちょうど「目次」**のときだけ動きます（「目次について」などでは動きません）
- 目次に載るのは**その見出しより下にある見出し**だけです
- 見出しのレベル（`##` / `###`）がそのまま入れ子になります
- 見出しの重複は自動で別々のリンクになります
- `.html` のページでも `<h2>目次</h2>` と書けば同じように動きます

### 一覧を自動生成する（特殊な見出し）

`## 目次` と同じ要領で、**見出しを置くだけで一覧が作られる**書き方が 4 つあります。
リンクを手で並べる必要はなく、ファイルが増えても勝手に追いつきます。

| 書き方 | 出るもの |
| --- | --- |
| `## タグページ一覧:設計` | そのタグが付いた全ページ |
| `## サブページ一覧:guide` | そのフォルダー配下をツリー表示 |
| `## ページツリー` | このページに至るまでのフォルダーと、同じフォルダーのページ |
| `## 関連ページ一覧:install` | 指定した文字列を含むページ |

```markdown
## サブページ一覧:/guide
```

出力はこうなります。フォルダー名もリンクなので、そのまま開けます。

```
guide/
├─ api/
│  └─ rest.md
├─ faq.md
└─ install.md
```

**書き方の決まり**

- 見出しが**まるごとその形**である必要があります。
  「サブページ一覧について」のような説明文には反応しません
- コロンは半角 `:` でも全角 `：` でも構いません
- `サブページ一覧` のフォルダー指定は 2 通りです
  - `guide` … **書いているページのフォルダーから見た相対パス**（`../reference` も使えます）
  - `/guide` … **ライブラリのルートから**の絶対パス
- `関連ページ一覧` が見ているのは**ファイル名・フォルダー名・タグ**です。
  **本文の中は見ていません。** 本文から探したいときは ☰ の「検索」を使ってください

### ページ内の見出しへ

見出しには自動で id が振られるので、そのまま飛べます。

```markdown
[サニタイズについて](#サニタイズについて)
```

id は「小文字化 → 記号を削除 → 空白をハイフンに」で作られます。
日本語の見出しはそのまま使えます。

| 見出し | id |
| --- | --- |
| `## Getting Started` | `getting-started` |
| `## 導入 手順` | `導入-手順` |
| `## Notes`（2 つ目） | `notes-1` |

### 外部サイト

`http://` `https://` で始まるリンクは**新しいタブ**で開きます。

```markdown
[SharePoint Framework](https://aka.ms/spfx)
```

### HTML ファイルへのリンク

`.html` もビューアーが表示するので、`.md` と同じようにリンクできます。
クリックするとページを再読み込みせずにその場で開きます。

```markdown
[仕様書（HTML）](spec/index.html)
```

### ビューアーが表示しないファイル

同じライブラリ内の PDF などにもリンクできます。これらはビューアーでは開かず、
SharePoint 側の処理（表示またはダウンロード）になります。

```markdown
[操作マニュアル](docs/manual.pdf)
```

> ### `..` でライブラリの外には出られません
>
> `../../../secret.md` のように書いてもライブラリのルートで止まります。
> また、`.md` / `.markdown` / `.html` / `.htm` 以外を `?file=` で開くことはできません。

## 3. 画像

画像もライブラリに置いて、相対パスで参照します。

`README.md`（ルート）から:

```markdown
![ロゴ](images/logo.png)
```

`guide/install.md` から:

```markdown
![サンプル](../images/sample.png)
```

- 画像は本文の幅に合わせて自動で縮小されます
- **外部サイトの画像 URL と `data:` 形式の埋め込み画像は表示されません**（セキュリティ設定のため）

## 4. 書ける記法

GitHub Flavored Markdown の主要な記法に対応しています。

### 見出し・段落・強調

```markdown
# 見出し1
## 見出し2

**太字** と *斜体* と ~~取り消し線~~ と `インライン コード`
```

### 箇条書き・番号付き

```markdown
- 項目
  - 入れ子
1. 手順
2. 手順
```

### チェックリスト

```markdown
- [x] 完了した項目
- [ ] これからの項目
```

### 表

```markdown
| 機能 | 説明 | 状態 |
| --- | --- | --- |
| 表示 | 見出し・表・コード | 実装済み |
```

幅が広い表は横スクロールになります。

### 引用・区切り線

```markdown
> 補足や注意はここに書きます。

---
```

### コードブロック

言語名を書くと色分けされます。

````markdown
```typescript
export function resolve(current: string, link: string): string {
  return link;
}
```
````

**色分けできる言語は次の 8 つです。**

`javascript` / `typescript` / `powershell` / `json` / `xml`（HTML） / `css` / `sql` / `csharp`

これ以外の言語名を書いてもエラーにはなりません。色が付かずそのまま表示されます。

## 5. 消える書き方

Markdown に埋め込んだ HTML のうち、危険なものは表示時に取り除かれます。
**書いても無視される**ので注意してください。

| 書いたもの | 結果 |
| --- | --- |
| `<script>` | 除去される |
| `<iframe>` `<object>` `<embed>` | 除去される |
| `<style>` `<form>` | 除去される |
| `onclick` `onerror` などのイベント属性 | 除去される |
| `style="..."` 属性 | 除去される |
| `[x](javascript:...)` | リンクが無効になる |

`<b>` `<strong>` `<code>` `<img>` `<a>` など、Markdown が生成するのと同じ範囲の
HTML タグは使えます。`.html` ファイルではもう少し広い範囲が使えます（10 章）。

## 6. タグを付ける

タグを付けておくと、同じタグが付いたドキュメントをライブラリ全体から一覧できます。

### 6.1 準備（最初の 1 回だけ）

ライブラリにタグを保存する**列**が必要です。無ければ作ります。

1. ライブラリ →「列の追加」
2. 型を選ぶ
3. 列名を付ける（例: `タグ`）
4. ページの Web パーツのプロパティ →「タグの列 1」で選ぶ（サイト編集権限が必要）

> **プロパティの一覧に `Title` しか出てこない場合**、それが正常です。
> 候補になるのは**そのライブラリにある** 1 行テキスト / 複数行テキスト / 選択肢 の列だけで、
> 既定のドキュメント ライブラリにはほとんどありません。上の手順で列を足すと出てきます。
> 日付・数値・ユーザー・管理されたメタデータの列は候補になりません。

**列は 3 つまで**設定できます（「タグの列 1」〜「タグの列 3」）。
性質の違う分類を分けたいときに使ってください。例:

| 列 | 例 | 型 |
| --- | --- | --- |
| タグの列 1 | `設計` `SPFx` `運用` | 選択肢（複数選択可） |
| タグの列 2 | `手順書` `リファレンス` `議事録` | 選択肢（単一） |
| タグの列 3 | 担当者名 | 1 行テキスト |

| 列の型 | ビューアーでの編集画面 | 向いている場面 |
| --- | --- | --- |
| 1 行テキスト / 複数行テキスト | 入力欄（`;` `,` `、` 区切り） | タグを自由に増やしたい |
| 選択肢（複数選択可） | チェックボックス | 表記ゆれを防ぎたい |
| 選択肢（単一） | ラジオボタン | 分類を 1 つだけ付けたい |

> 管理されたメタデータ（用語ストア）の列には対応していません。
> 列を追加した直後は、プロパティ ウィンドウを開き直すと一覧が更新されます。

### 6.2 タグを付ける

ビューアーで対象のドキュメントを開き、右上の **「タグ」** ボタンを押します。
列の型に応じた入力画面が出るので、選んで（または入力して）「保存」します。

ライブラリの一覧画面から直接列を編集しても同じです。

**タグの保存にはライブラリの編集権限が必要です。**

### 6.3 一覧に無いタグを付ける

タグの編集画面の各段にある **「新しいタグを追加」** に入力すると、
選択肢に無いタグでもその場で付けられます（`;` か `,` で複数指定できます）。

選択肢の列に新しいタグを付けると、**その列の選択肢にも追加されます**。
これにはライブラリの設定を変更できる権限が必要です。権限が無い場合は、
列の設定で「選択肢に無い値を入力できるようにする」を有効にしておいてもらってください。

### 6.4 タグをクリックすると

ページ冒頭のタグをクリックすると、**そのタグが付いたページをライブラリ全体から探して一覧**にします。
フォルダーをまたいでライブラリ全体を探します。

### 6.5 タグの探し方

- 一致の判定は**3 つの列をまとめて**行います（どの列のタグでも構いません）
- 大文字小文字は区別しません（`SPFx` と `spfx` は同じ）
- 探す範囲はライブラリ全体です（フォルダーを問いません）

## 7. 書いたものを確認する

### ビューアーで見る

```
https://<テナント>.sharepoint.com/sites/docs/SitePages/SpWiki.aspx?file=guide/install.md
```

`file=` にはライブラリのルートからの相対パスを書きます。

ライブラリで `.md`（または `.html`）を選んで、ツールバーか右クリック メニューの
**「Markdown プレビュー」** でも確認できます。

### 編集する

| 方法 | 手順 |
| --- | --- |
| SharePoint 上で編集 | ビューアー右上の **「編集」** ボタン |
| パソコンのエディターで編集 | ビューアー右上の **「アプリで開く」** ボタン |
| ライブラリから | `.md` を選んで右クリック →「デスクトップ アプリで編集」 |

「アプリで開く」は `spmd:` という専用の合図でパソコンのアプリにファイルを渡します。
**対応したアプリが入っていないと何も起きず**、少し待つとその旨が表示されます。
管理者側の準備が要るので、必要であれば相談してください。

## 8. 書き方のコツ

- **`README.md` をライブラリのルートに置き、目次にする。** 開始ファイルの既定値なので、
  URL にパラメーターを付けずに開いたときの入口になります
- **フォルダーごとに `index.md` を置く。** そのフォルダーの入口として使えます
- **リンクは相対で書く。** サイトを移動しても壊れません
- **画像は `images` フォルダーにまとめる。** 参照が `../images/...` で一定になります
- **タグは少なめに、粒度を揃える。** 検索結果が増えすぎると役に立ちません

---

## 9. うまくいかないとき

| 症状 | 確認すること |
| --- | --- |
| リンクを踏んでも「見つかりません」 | パスの綴りと大文字小文字。相対の基準は**そのファイルがあるフォルダー**です |
| 画像が出ない | ライブラリ内に置いてあるか。相対パスが合っているか。外部 URL は表示されません |
| 表が崩れる | 区切り行（`| --- |`）が列数と合っているか |
| コードに色が付かない | 対応している 8 言語かどうか（4 章） |
| 書いた HTML が消える | 5 章の除去対象に入っています |
| `.html` のデザインが反映されない | 仕様です。10 章を参照してください |
| タグが出ない | 管理者が Web パーツのプロパティで「タグの列」を設定したか |
| 文字化けする | ファイルを UTF-8 で保存してください |

## 10. HTML ファイルを置く

`.html` / `.htm` も `.md` と同じようにライブラリに置くだけで読めます。
Markdown の記法は解釈されず、書いた HTML がそのまま（ただしサニタイズを通って）表示されます。

### `.md` と同じもの

| 項目 | 動作 |
| --- | --- |
| 相対リンクの解決 | `install.md` `../top.html` などを、そのファイルの位置を基準に解決します |
| リンクのその場移動 | `.md` ⇔ `.html` を跨いでも再読み込みせずに移動します |
| 画像の相対パス | `<img src="../images/sample.png">` を解決します |
| 見出しの id | `<h2>` などに自動で id が振られ、`#見出し` で飛べます |
| コードの色分け | `<pre><code class="language-typescript">` と書くと色が付きます |
| サニタイズ | 5 章の表とまったく同じ設定を通ります |
| タグ・タグ検索 | `.md` と同じように扱われます |

### `.md` と違うもの

- **見た目はビューアー側の体裁になります。** ファイルに書いた `<style>` と `style` 属性は
  除去されるため、配色・フォント・段組みなどの指定は反映されません。
  `.md` と `.html` が混在しても同じ見た目で並ぶようにするための仕様です
- `<html>` `<head>` `<body>` を含む完全な HTML ファイルでも構いません。
  `<head>` の中身（`<title>` や `<style>`）は表示されず、本文だけが描画されます
- `<script>` `<iframe>` `<form>` は除去されます。動きのあるページは作れません

### 使える要素

Markdown が生成する要素（見出し・段落・表・リスト・コード・引用・リンク・画像など）に加えて、
次の要素が使えます。

`figure` / `figcaption` / `caption` / `details` / `summary` / `section` / `article` /
`header` / `footer` / `aside` / `nav` / `main` / `dl` / `dt` / `dd` / `abbr` / `cite` /
`q` / `small` / `mark` / `u` / `time`

一覧にない要素は、タグだけが外れて中の文字は残ります。

### 向いている場面

- 他のツールから書き出した HTML をそのまま置きたい
- 表の結合セル（`colspan` / `rowspan`）など、Markdown で書けない構造がある
- `<details>` の折りたたみを使いたい

見た目を作り込みたい場合には向きません。その用途では SharePoint のページを使ってください。
